# 07 — B8: Session-Safe Planner State & History

**What to build:** Partition planner step histories and multi-turn conversational context in `server/main.py` by composite key `session_id + task_id + step` to prevent state collision across concurrent tasks and sessions.

**Blocked by:** 01 — B1: Real VLM Planner Backend

**Status:** ready-for-agent

## Context & Details
- Target files: `server/main.py`, `server/tests/test_server.py`
- Current behavior: In-memory `_step_history` is keyed by raw `task` string alone.
- Multiple browser tabs or users running identical tasks (e.g. "Fill out registration form") clobber each other's step history, resulting in confused loop termination and wrong actions.

## Acceptance Criteria
- [ ] Schema updated to require `session_id` (UUID generated by client extension per agent run) and `task_id`.
- [ ] Planner state and history storage keyed by `(session_id, task_id)` composite key.
- [ ] Inactive sessions automatically expire or clean up after configurable timeout to prevent memory leak.
- [ ] Concurrency test executes two simultaneous sessions with the exact same task string and asserts zero cross-talk between step histories.
